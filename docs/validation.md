## B2：空闲过夜后的内存压力与权重锁定（2026-10-01，Mac Studio）

**现象**（用户报告）：服务空闲约 10 小时（服务日志在 03:28 之后没有任何请求），回来时内存压力稳定为黄色。

**agent 只读诊断（13:10）**

| 指标 | 03:40 | 13:10 |
|---|---|---|
| worker 常驻内存 | 77.6 GB | 20.2 GB |
| 系统 wired 内存 | 约 78 GB | 3.9 GB |
| 压缩器占用 | <1 GB | 53.3 GB（存放 53.5 GB 的页） |
| swap | 0.5 GB | 3.1 GB |
| 内存压力等级 | 1 | 2（warn） |

- 结论：空闲期间模型的 GPU 内存不再被锁定，系统需要内存时把模型压缩进压缩器；但 4-bit 权重几乎压不动（约 1:1），没有腾出内存，压缩器占满使压力保持黄色，还写了约 3 GB 的 swap；下一个请求要先把这 53 GB 解压回来。MLX 的 `set_wired_limit` 文档只说「保持常驻」，没有说明空闲很久之后的行为。与 agent 凌晨误跑的测试无关（03:40 时 worker 仍全部常驻、压力正常）。
- 用户的决定：只做「锁定权重」，不做空闲卸载（大内存就是为模型准备的，日常使用 16–20 GB 足够；需要时手动 stop）。
- 实现：加载完成后对全部权重缓冲区调用 `mlock`（bfloat16 通过同尺寸整数的 view 取得地址；小模型上验证 view 与原数组共享内存，锁定后系统 wired 增量等于锁定的字节数）。本机单进程最多可锁 78.7 GB（`vm.user_wire_limit`），macOS 另外保留 17.3 GB 永不被锁。锁定失败则 worker 启动失败。`locked_bytes` 出现在 worker 就绪日志与 `/health/runtime`。
- agent 已验证（服务停止，带硬性前置检查）：后端全部 130 个测试通过，新增：锁定的字节数等于全部权重数组（含草稿模型）的大小，真实 worker 进程的 `/health/runtime` 报告锁定字节数。
- **尚未验证**：真实模型上的锁定（约 68 GB）与空闲过夜后 worker 仍全部常驻、压力保持正常。
